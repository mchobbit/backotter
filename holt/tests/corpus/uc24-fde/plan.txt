#   - Ubuntu Core: the LUKS2 header files the dump kept (by default in /run/bko-holt/luks-headers, RAM) must be kept with the dump: load reads them beside the layout, or in --luks-header-dir
#   - Ubuntu Core with TPM-sealed FDE: both LUKS2 headers come back byte for byte. On the same machine (the same TPM and Secure Boot variables, dbx included) it boots unattended only if nothing was resealed since the backup: a kernel, gadget or snapd refresh or a new recovery system after it reseals the keys and advances the TPM's policy counter, which revokes the restored sealed keys. On another TPM, after a firmware or dbx reset, or after such a reseal, run mode can't unlock and reboots in a loop: load with --new-machine, whose first boot is recover mode
#   - Ubuntu Core: the gadget's BIOS Boot partition is empty (the pc gadget of UC24 boots by UEFI only; its MBR code says "Please boot in EFI mode"), so the restored disk boots by UEFI only, as the source did
#   - Ubuntu Core finds its partitions by label: boot the restored disk with the source's disk (or any other Ubuntu Core disk) detached
#   - Ubuntu Core: ubuntu-seed, ubuntu-boot, ubuntu-save and ubuntu-data are restored as they were; no grub-install, no update-grub, no initramfs, no chroot, and no UEFI entry (shim's fallback on the restored seed makes it at the first boot)
