F4  none.
F5  S3, crates/core/src/backend/osattrs/illumos_acl.rs:82 split_sid: a wrong
    Ok.  It checks that the whole SID starts with "S-", not that the prefix
    does, so "S-1" splits as ("S", 1).  idmap_sid_to_id (illumos_idmap.rs:167)
    then hands libidmap the prefix "S" for a SID from a snapshot, instead of
    refusing it as "malformed SID".  Evidence: acl_and_sids_malformed,
    'cut "S-1": split as ("S", 1)' (Cinqcent native, and every ASan/TSan
    lib run).  Fix: test prefix.starts_with("S-") (or require a digit
    after "S-" and at least one more '-').  The test fails until it is fixed.
F6  none.  ASan/TSan clean over the restore unit and integration tests on
    four file systems; parity PASS.
F7  none.  ASan clean over local_destination's tests and walkdir's longpath
    and noatime tests with TMPDIR on tmpfs, ext4, xfs, btrfs; Miri can't run
    them (mkdirat, O_NOATIME, statfs).
F8  none in our lines.  Upstream, inherited, noted: a node time before the
    host zone's standard time is written with the zone's local-mean-time
    offset, whose seconds RFC 3339 drops.  Europe/Paris before 1891 is
    +00:09:21, so the time is written as "1850-06-01T12:09:21+00:09" and
    reads back 21 s late.  It drifts again each time a node is rewritten
    (rewrite, copy, merge, repair).  rustic_core's RusticTime
    (repofile.rs:131) passes TimeZone::system()'s offset.  Our hunk
    timestamp_to_string (repofile.rs:137-148, ef1dab5) only adds "Z" for UTC
    and keeps that.  restic-bko does the same.  Writing UTC whenever the
    offset has seconds would fix both, but it changes tree bytes and needs
    the user's decision (D3).
    Evidence: the node test's first run (3 wrong: mtime/atime/ctime "0026-"
    read back 21 s off) and the by-hand 1850 run above.
F9  none from F2: the rustic CLI was exercised only as rustic-bko in the
    parity runs.
Upstream, out of scope: repair_snapshots' order dependence (above).
